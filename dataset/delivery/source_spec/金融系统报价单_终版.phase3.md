## 第 1 页

金融垂直领域 Graph RAG 系统技术方案与报价单

一、 项目背景与目标

本项目旨在针对金融股票投资场景，基于私有化本地部署的大语言模型与 Graph RAG

（知识图谱增强检索）技术，打造一个高精度、防幻觉的智能投研问答系统。

系统支持多源异构数据（如纯文本会议纪要、微信公众号文章、复杂的上市公司年报及招

股说明书 PDF）的深度解析、知识抽取与融合，从而辅助投资决策与研报分析。

二、 核心技术架构选型

1. 底层操作系统：Ubuntu 24.04 Desktop

2. RAG 核心框架：WeKnora（支持混合检索、多模态及知识图谱）

3. 本地大模型：Qwen 3.6/2.5 系列 35B

4. 向量与重排序：行业领先的 qwen3-embedding-8b 和qwen3-reranker-0.6

5. 图数据库引擎：支持框架原生图库或 Neo4j

6. 文档解析组件：专项金融 PDF 深度解析库（处理跨页表格、财务报表）

四、 核心调优技术方案

针对传统开源 RAG 在金融场景下经常翻车的痛点，我们将部署以下独门调优策略：

1. 金融级复杂 PDF 解析攻坚

痛点：传统的普通 RAG 读取年报 PDF 时，面对大量的“跨页无框表格”和“密集财务脚

注”，读出的全是乱码错位，导致模型疯狂胡说八道。

我们的方案：将抛弃传统解析，直接接入针对复杂排版训练的顶级多模态文档解析模型

（如 MinerU 或 Docling 引擎）。通过版面分析，将财务报表强制剥离并转置为带严格

结构的 Markdown 表格，并绑定上下文元数据，从根源确保底层财务数据“不丢数、不

错位”。

2. 知识图谱 Graph RAG 注入

痛点：传统的向量相似度搜索只会找“字面意思相近”的词。如果问“综合分析A 公司年

报里的前五大客户，是否潜伏在B 公司招股书的供应商名单里？”，传统 RAG 完全无法

应对这种需要关联的深度逻辑。

我们的方案：在数据建库阶段，利用 35B 级大模型后台静默阅读，自动从海量文字中抽

取出【投资机构、高管人员、上下游供应链、竞争对手】等实体关系网络，存入专门的图

数据库。检索时，系统会先在知识图谱中“顺藤摸瓜”圈出实体关系子图，再结合向量文

本，真正具备资深研究员级别的关联推理能力。

3. 混合检索与特定金融词典兜底

痛点：即使模型再强，有时候依然会对特定的金融“黑话”（如：扣非净利润、定增倒

挂、ROE）不够敏感，容易答非所问。

我们的方案：采用 Dense 稠密语义向量 + Sparse 稀疏关键词的双路混合检索架构

（Hybrid Search），并外挂专业金融核心词表。检索结束后，通过金融领域专属增强的

重排序模型（BGE-Reranker-v2 进行最终的二次裁判。确保就算查询词极其专业刁钻，

也能在百万字文档中被高权重的引擎精准打捞上来。

4. 动态语义分块策略（Semantic Chunking）

痛点：粗暴的按字数切片（比如强行500 字切一刀）很容易把一段核心的金融逻辑链条一

刀两断，严重破坏上下文。

我们的方案：摒弃固定字数切割，改为根据文档自带的篇章结构（按一级标题、自然段

落、甚至完整的表格边界）进行智能语义切块，让喂给大模型的每一个上下文片段都具备

完整的业务逻辑意义。

五、 客户需知与配合事项

1. 硬件算力：本报价为纯软件技术服务。客户需自行准备本地算力服务器（建议配备至少

24GB 显存的 GPU，如单张 RTX 3090 或 4090）。

2. 数据脱敏：如需提供企业微信记录等真实内部文档用于调优，请提前进行核心商业信息

的脱敏处理。

3. 运维移交：交付后将提供完整的本地启停命令与系统维护指导，后续常规文档上传与查

询均由贵方业务人员自行可视化操作。

六、付费方式

1、首付款200 元，双方达成同意，执行本次的项目

2、双方同意最终达到终极高精度版本，按照阶段进行交付，然后按照阶段验收后进行付

费。

3、本次项目完成后，项目开发方需要维持1 个月的咨询服务，帮助解决出现的问题。
